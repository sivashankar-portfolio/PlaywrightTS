Playwright Visual Testing Practice

Each card demonstrates something visual-regression tests commonly deal with: dynamic content that needs masking, running animations that need disabling, hover/focus/active states, loading skeletons, responsive layouts, and theme switches. Snippets show the toHaveScreenshot() pattern to try.

Full Page Screenshot

Compare the Whole Page

Baseline is created on first run; subsequent runs diff against it pixel-by-pixel.

Comparison Thresholds

Tolerating Minor Pixel Noise

Anti-aliasing and font rendering differ slightly across OS/CI machines — thresholds absorb that noise without hiding real regressions.

await expect(page.locator('#basic-price-card')).toHaveScreenshot('price-card.png', { maxDiffPixelRatio: 0.02, // allow up to 2% of pixels to differ threshold: 0.2 // per-pixel color-difference sensitivity (0-1) });

Introduce a Visual Bug on Purpose

Broken Nav Padding
HomeProductsAboutContact
// 1) Capture the baseline with the bug class OFF await expect(page.locator('#nav-demo')).toHaveScreenshot('nav-baseline.png'); // 2) Click "Toggle Layout Bug", then compare against the SAME baseline name await page.getByRole('button', { name: 'Toggle Layout Bug' }).click(); await expect(page.locator('#nav-demo')).toHaveScreenshot('nav-baseline.png'); // ^ This assertion should now FAIL with a visible diff highlighting the extra top padding.
This is the core visual-regression workflow: run once to record the baseline, change the UI, re-run to watch it fail, then run with --update-snapshots once the change is intentional.

Updating Baselines

CLI Reference
# Run tests and generate/compare screenshots npx playwright test # Accept the current rendering as the new baseline (after an intentional UI change) npx playwright test --update-snapshots # Run only visual tests, useful once they live in their own file/project npx playwright test visual.spec.ts
Baselines are OS-specific by default (chromium-darwin, chromium-win32, ...) — commit the ones matching your CI runner, or generate them inside a Docker/CI run so local and CI platforms don't fight over pixel differences.
